# 「作业伙伴」——四年级学生作业打卡 × 电子宠物养成

> 产品设计方案 v1.0
> 目标用户：小学四年级学生（9–10 岁）+ 家长

---

## 0. 一句话定位

把"做作业"从**家长催促的外部压力**，转化成**孩子自己想去完成的日常循环**——通过一只需要她照顾的电子宠物，把"我被要求写作业"改写成"我要照顾好它"。

---

## 1. 设计原则（后面所有功能都服从这五条）

| # | 原则 | 具体含义 |
|---|------|---------|
| 1 | **正向为主，惩罚为辅** | 损失厌恶（怕宠物死）短期有效，长期容易引发焦虑或"破罐破摔"。奖励要是主旋律，惩罚只做提醒。 |
| 2 | **孩子掌控感** | 打勾这个动作**必须由孩子本人完成**，家长不能代劳。这是整个产品的心理支点。 |
| 3 | **低摩擦** | 孩子每天用 ≤ 3 分钟，家长录入 ≤ 30 秒。一旦变成新负担，一周就废。 |
| 4 | **接受不完美** | 孩子会假打勾。设计上接受它，用"家长确认/抽查"而不是强管控——管控会摧毁信任，而信任才是这个 App 的资产。 |
| 5 | **可持续 > 强刺激** | 宁可激励弱一点，也要能撑三个月。第 30 天还在用，比第 3 天很兴奋重要得多。 |

---

## 2. 核心循环

```
      家长/孩子录入今日作业
                ↓
        孩子看到今日清单
                ↓
   ┌──→  完成一项 → 打勾  ←──┐
   │            ↓            │
   │   宠物立刻有反应        │
   │  （跑过来吃 + 音效 +    │
   │    饱食度上涨 + 经验）  │
   │            ↓            │
   └──── 还有未完成项 ───────┘
                ↓
        当天全部完成
                ↓
   连击 +1 / 额外积分 / 宠物特殊动画
                ↓
        积分 → 装扮、道具、现实奖励
```

**关键设计**：反馈必须**即时**。打勾到宠物有反应之间不能超过 300ms，且反应要有分量（动画 + 音效 + 数值跳动三重反馈）。这是整个产品最需要打磨的 3 秒。

## 3. 功能模块

### 3.1 模块 A：今日作业清单

**基础形态**
- 卡片式列表，每项包含：学科图标 / 作业内容 / 预计时长 / 打勾框
- 已完成项划线+淡出到底部，未完成项置顶（有进度感）
- 顶部进度条："今天 3/5 完成"

**打勾交互（重点打磨）**
- 大号点击区（孩子手指精度低），带触感反馈
- 勾选动画：勾 → 变成小食物 → 抛物线飞向宠物 → 宠物接住吃掉
- 允许**误触撤销**（3 秒内可反悔）

**家长录入方式（决定生死的功能）**
按优先级实现：
1. **一键复制昨天** ——小学作业高度重复，这一条能解决 60% 的录入
2. **常驻日常项** ——"每天阅读 20 分钟""口算题卡 1 页"自动每天生成
3. **模板库** ——预置常见项（语文抄写/数学口算/英语朗读/背诵/预习），点一下加一条
4. **手动添加** ——自由文本
5. *（后期）* 粘贴老师群里的作业文字，自动按行拆成条目

> ⚠️ 录入成本是这类 App 的第一死因。如果家长每天要花 2 分钟录入，两周内必然放弃。

**可选：专注计时**
- 点开某项 → 开始计时 → 全屏专注模式（宠物在旁边陪着写）
- 计时完成额外给一点积分
- **必须可关闭**，不要让计时变成新的压力源

**任务粒度建议**
- 每天 4–8 项最合适。少于 3 项没有成就感，多于 10 项会让孩子畏难
- 大任务要拆（"写作文" → "列提纲 / 写正文 / 检查错别字"）
- **不做"部分完成"**——保持二元状态，简单即是力量

### 3.2 模块 B：电子宠物（核心）

#### 属性系统（只保留三个，不要做成复杂养成游戏）

| 属性 | 范围 | 变化规则 | 作用 |
|------|------|---------|------|
| **饱食度** | 0–100 | 随时间衰减，完成作业回升 | 主驱动力，制造"该去做作业了"的提醒 |
| **心情** | 0–100 | 由连续打卡天数 + 当日完成率决定 | 影响宠物表情/动作，情感联结 |
| **成长值** | 只增不减 | 每完成一项 +1 | **保证长期投入永不白费**（关键的心理安全垫） |

#### 饥饿衰减模型（具体数值）

- 满值 100，**每小时衰减 ~1.5 点**，即 24 小时掉约 36 点
- 三天不管 → 归零

**喂食量必须按"当日完成率"算，而不是按项数：**

```
单项喂食量 = 40 / 当日作业总数
当日 100% 完成 → 恰好 +40（略高于一天的自然消耗 36）
当日 50% 完成  → +20（会缓慢变饿）
```

> 为什么这样设计：如果按固定值喂食，作业多的一天反而更容易养宠物，作业少的一天喂不饱——孩子会觉得不公平，而且会诱导家长多加作业。按完成率结算才是对的。

**全部完成额外奖励**：+15 饱食度 + 心情回满 + 特殊动画（宠物打滚/放烟花）

**假期模式**：周末/寒暑假可开启，衰减减半或暂停。不开启也行——很多家庭希望周末也保持节奏，做成开关。

#### ⚠️ 关于"饿死"——我建议改一下

你原始想法里"长时间不喂就饿死"，我理解意图（真实的失去感 = 强激励），但对 9–10 岁孩子有两个实际风险：

1. **真实的情绪伤害**：这个年龄对虚拟宠物有真实情感投入，永久死亡可能带来真实的悲伤和内疚。孩子还会生病、出门旅行、参加活动——这些不可抗力导致的"死亡"尤其伤人。
2. **激励系统会彻底失效**："反正已经死了" —— 一旦触发，孩子大概率直接弃用 App，而不是更努力。行为设计上这叫**吸收态**（进去了出不来），是要极力避免的。

**建议做成三档，家长在设置里选：**

**① 温和模式（默认推荐）**
- 饱食度 < 30：宠物打蔫，颜色变暗，说"我有点饿了……你今天的数学写了吗？"
- 饱食度 = 0：宠物生病（灰色、头顶小雨云），停止成长，但**不会死**
- 恢复：完成任意作业即开始恢复，当天完成全部作业即痊愈

**② 标准模式**
- 饱食度归零后再挂 2 天 → 宠物"离家出走"，界面留一张它的照片和一封信
- 找回方式：连续 2 天完成全部作业 → 它自己回来了（有个感人的回归动画）
- **等级、成长值、成就全部保留**

**③ 硬核模式（真的死亡）**
- 归零后 3 天 → 宠物死亡，需要重新领养一只（从蛋开始）
- 但上一只进入 **"回忆相册"**，记录它活了多少天、吃过多少顿饭、陪你完成了多少作业
- 把"失去"转化为"纪念"，而不是纯粹的惩罚

#### 必备的"保护机制"（无论哪档都要有）

- **请假卡**：每月发 2 张，孩子自己决定何时使用（用掉当天不衰减）。让孩子自己管理"额度"，本身就是很好的自主权教育。
- **离线保护**：家长可开启（生病、旅行、家庭活动），期间暂停衰减。
- **预警前置**：在真正出事前，必须有明确、多次、温和的提醒——不能让孩子觉得"莫名其妙就死了"。

#### 宠物成长与进化（长期留存的关键）

```
蛋 (第0天)
  ↓ 累计完成 10 项
幼体 (可爱、圆滚滚)
  ↓ 累计 40 项 + 连击 ≥ 7
成长期 (开始有性格)
  ↓ 累计 120 项 + 连击 ≥ 21
成熟体 (分支进化)
```

**分支进化按学科占比决定**（很有意思的机制）：
- 数学完成最多 → **智慧型**（戴眼镜、会解题）
- 语文/阅读最多 → **文艺型**（拿本书、会写诗）
- 英语最多 → **旅行型**（背包、会说外语）
- 各科均衡 → **全能型**（隐藏进化，最稀有）

> 这个设计的妙处：孩子想要"全能型"，就会主动去补自己不爱做的那一科。用游戏机制解决偏科，比说教有效。

**进化节点的时间安排**要卡在新鲜感衰退的位置：第 7 天、第 21 天、第 45 天各有一次大变化。

### 3.3 模块 C：激励与反馈层

- **连击（Streak）**：连续完成天数，最显眼的数字。中断有一次"保护"（每月一次自动续上）
- **日历热力图**：一个月的完成情况一目了然，绿色格子越多越有成就感
- **成就徽章**（示例）：
  - 初来乍到 / 连续 7 天 / 连续 30 天 / 单月全勤
  - 早鸟（20:00 前完成全部）/ 数学小能手（数学连续 10 次）
  - 从不迟到 / 宠物养到成熟体 / 全能进化
- **每周小结**：家长和孩子**一起看**
  - 本周完成率、最常拖延的科目、宠物成长曲线
  - 语气要是"我们一起看看这周"，不是"检查你"
- **积分商店**：完成作业得积分 →
  - 虚拟：宠物帽子/衣服/房间装饰/新宠物解锁
  - **现实奖励（重要）**：家长自定义兑换表，比如
    - 100 分 = 周末多玩 30 分钟
    - 300 分 = 选一部电影全家看
    - 800 分 = 一次公园/游乐场
  > 纯虚拟奖励对 9–10 岁孩子的效力会在 4–6 周后明显衰减，必须有现实桥接。

---

### 3.4 模块 D：家长端

访问方式：设置里长按/输入 4 位密码进入（防止孩子改数据）

- **录入作业**（见 3.1）
- **确认模式开关**
  - *信任模式*：孩子打勾即生效（推荐先用这个）
  - *确认模式*：孩子打勾后待确认，家长确认后才喂食
- **规则设置**：惩罚档位、假期模式、衰减速度、每日提醒时间
- **奖励兑换表**：自定义现实奖励
- **数据报告**：周/月报、各科完成率趋势
- **给家长的提示卡**（我很推荐加这个）
  - "数学连续 3 天没完成——可能是遇到困难，而不是偷懒，找个时间聊聊"
  - "这周完成率下降了，但别急着批评，先问问最近怎么样"
  - 让 App 不只是管孩子的工具，也轻轻地帮到家长

---

### 3.5 模块 E：可选进阶（后期考虑）

- 错题拍照存档 + 复习提醒
- **家长录音鼓励**：全部完成时播放妈妈/爸爸的一句话（这条成本极低但效果极好）
- 多孩子账号
- 宠物之间的互动（表兄弟姐妹之间），涉及隐私要谨慎，建议只做"家庭内"

## 4. 界面与视觉

### 主界面结构（从上到下）

```
┌────────────────────────────┐
│ 🔥7天  ⭐Lv.4  ❤️████░ 80  │ ← 状态条
├────────────────────────────┤
│                            │
│         🐣                 │ ← 宠物区（占 40% 屏幕，会动）
│      「小豆」               │
│    今天心情不错～           │
│                            │
├────────────────────────────┤
│ 今日作业        3/5 ▓▓▓░░  │
│ ☑ 数学 口算题卡1页          │
│ ☑ 语文 抄写词语             │
│ ☑ 英语 朗读Unit3            │
│ ☐ 语文 背古诗《望庐山瀑布》  │
│ ☐ 科学 观察记录             │
└────────────────────────────┘
```

### 视觉与体验要点

- **宠物必须"活着"**：待机时会眨眼、走动、打哈欠；被点击有反应（害羞/开心）；饿的时候动作变慢；完成作业时冲过来吃
- **风格**：明亮、圆润、低饱和高明度。**但不要太幼稚**——四年级孩子已经开始嫌弃"幼儿园的东西"了，可以偏向"清新可爱"而不是"婴幼儿"
- **音效**：打勾"叮"、进食、升级、全部完成的小号声。**必须能一键静音**（写作业环境）
- **护眼**：字号偏大、深色模式、连续使用 20 分钟提醒休息
- **不做的事**：不做无限滚动、不做红点轰炸、不做"再看一个"的诱导设计。这是给孩子的工具，不是要抢占时间的产品

## 5. 技术方案

### 推荐：纯前端 Web App（PWA）+ 本地存储

**为什么：**
- 跨设备：手机 / iPad / 电脑浏览器都能开，不用分别开发
- 零安装：发个链接就能用，"添加到主屏幕"后跟原生 App 一样
- 免费部署：GitHub Pages / Vercel / Cloudflare Pages
- **零隐私风险**：数据只存在设备上，不上传任何服务器——给孩子做的东西，这点很重要

**技术栈：**
- React + Vite + TypeScript
- Tailwind CSS
- 宠物动画：CSS/SVG 动画起步（足够了），后期可换 Lottie / Rive
- 存储：localStorage（简单）或 IndexedDB（数据多时）
- 备份：一键导出/导入 JSON 文件

### 几个必须处理对的技术点

**① 饥饿计算用"时间戳差值"，不能用定时器**
```
当前饱食度 = 上次结算值 - (现在 - 上次结算时间) × 衰减速率
```
关掉 App 也在饿，打开时结算一次。这是所有养成类应用的标准做法。

**② 防作弊：改系统时间**
孩子会想到把手机时间往回调。对策：单独记录一个"历史最大时间戳"，如果当前时间小于它，就忽略这次读数、按最大值算。不用做得太复杂，能挡住随手尝试就够了。

**③ 日切时间设在凌晨 4:00，而不是 0:00**
避免晚上 11 点写完作业、打勾时已经算"明天"的尴尬。

**④ 提醒通知**
- PWA Web Push：Android/桌面支持好，**iOS 支持有限**（需已添加到主屏，且系统版本较新）
- 兜底方案：家长端每天固定时间的手机日历提醒/闹钟

### 如果需要多设备同步

场景：家长在自己手机上录作业，孩子在 iPad 上打勾。这时纯本地就不够了，需要：
- **轻量后端**：Supabase（免费额度足够，自带数据库+认证）或 Cloudflare Workers + D1
- **或者极简方案**：家长录入后生成一个二维码/短口令，孩子端扫码导入当天作业（不需要后端，但每天要操作一次）

> 建议：先做纯本地版本跑两周，验证孩子真的会用，再决定要不要上同步。

## 6. 防作弊：务实的态度

孩子一定会有假打勾的时候。我的建议是**不要用技术手段强管控**，因为：
- 管控会把 App 从"我的宠物"变成"监视我的东西"，孩子立刻抵触
- 而且技术上也管不住

可用的**轻量摩擦**（都是可选的）：
- 打勾后弹一个输入框："这项做了什么？"（一句话即可，也可跳过）
- 家长确认模式（每天花 10 秒扫一眼）
- 每周随机抽查一项，抽中的正确完成有额外奖励（把抽查变成奖励而非惩罚）

**核心心态**：这个 App 的目标是**建立习惯**，不是**保证真实性**。假打勾几次没关系，只要她每天愿意打开、愿意想起"我该写作业了"，就已经成功了一大半。

| 版本 | 内容 | 工作量 |
|------|------|--------|
| **V0.1 MVP** | 今日作业清单 + 打勾 + 一只宠物 + 饱食度 + 本地存储 + 基础动画 | 1–2 天 |

| **V0.3** | 家长端（密码、录入优化、设置、周报）+ 积分商店 + 现实奖励兑换 | 2–3 天 |

**强烈建议**：V0.1 做出来先让女儿用一周，观察她的真实反应，再决定 V0.2 做什么。她的实际使用行为会推翻我们现在的一半假设。

## 8. 真实风险（必须提前知道）

| 风险 | 说明 | 对策 |
|------|------|------|
| **新鲜感衰退** | 最大的风险。2–4 周后兴趣会明显下降 | 进化节点卡在第 7/21/45 天；后续加新宠物、季节活动、节日皮肤 |
| **家长录入疲劳** | 这类 App 的第一死因 | 一键复制昨天 + 常驻日常项，把录入压到 30 秒内 |
| **动机挤出效应** | 心理学上的 overjustification：外部奖励可能反而削弱本来存在的内在动机 | 随时间把奖励从"每次必给"逐步转向"偶尔惊喜"；周报强调进步和努力，不强调数量 |
| **变成监控工具** | 孩子一旦感觉被监视，会强烈抵触 | 宠物是"她的伙伴"，家长视角要克制；不要拿数据当质问的证据 |
| **惩罚适得其反** | 宠物死了 → 直接弃用 | 用温和模式 + 请假卡 + 可恢复机制（见 3.2） |
| **孩子觉得幼稚** | 四年级已在审美过渡期 | 视觉不能太低龄；进化后的形态要"帅"/"酷"一点 |

## 9. 一个很有效的技巧：让女儿参与设计

这条的效果可能比上面所有功能加起来都大——

- 让她**给宠物起名字**
- 让她**从几个形象里选一个**（或者干脆让她画，你把她的画扫描进去当素材）
- 让她**参与制定现实奖励兑换表**（她定的价格，她自己会认）
- 上线前跟她说"这是爸爸给你做的，你来提意见"

参与感 → 归属感 → 她会主动想用。而且这个共同创作的过程本身，可能比 App 本身更有价值。

## 10. 需要你确认的几个决定

1. **孩子主要在什么设备上用？**（手机 / iPad / 电脑）——影响布局优先级
2. **惩罚强度选哪档？**（建议先用温和模式，观察一段时间再调）
3. **家长录入在哪里做？**（同一设备 → 纯本地即可；不同设备 → 需要同步方案）
4. **宠物形象**：用现成的可爱形象，还是让女儿参与设计？
5. **现实奖励兑换表**：这个建议你和她一起定，我这边留好配置入口
