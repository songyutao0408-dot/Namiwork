# 纳米Work「动态网页交付」UI 动效片 —— Prompt

> 改编自 awesome-opus5-5-videos 中 @verbove 的 UI 动效模板（"One shape, never cut"），并参考 @AnnaCher___ 的风格约束。
> 所有产品事实、文案均来自 `docs/纳米Work产品背景.md`，不得补充资料之外的功能、数据或案例细节。
> 本 prompt 的执行结果见同目录下的 `delivery-film.html`。

---

<inputs>
产品：纳米Work（360 出品，新一代 AI 工作平台）
口号：一人成军，百事可托
要讲的故事：纳米Work 不只给答案或文件，而是直接交付一个可用的网址 —— 生成 → 验收 → 分享 → 更新。

UI 状态（按顺序，共 12 个）：
1. Logo：圆角方块，内写"纳"
2. 输入框：用户打字「把每天的广告投放数据做成一个看板，手机上也能看」
3. 发送按钮被点击 → 胶囊提示「专家团已接单」，三个专家头像：数据 · 设计 · 开发
4. 【可生成】浏览器窗口：看板逐块搭出来（指标卡、折线图自己画出来、柱状图长出来）
5. 【可验收】扫描线扫过页面，清单逐条打勾：页面展示 / 按钮点击 / 页面跳转
6. 【可验收】窗口收窄成手机：检查手机端适配，发现一处问题 → 自动修改 → 打勾，"验收完成再交付"
7. 【可分享】手机变成分享卡：二维码 + 「复制链接」按钮，光标点击 → toast「链接已复制」
8. 分享卡底部文案：发给客户、团队、投资人 · 无需安装，点开即用
9. 【可更新】对话气泡打字「加一个按渠道对比的图」
10. 看板重新排版，新图表长出来，版本胶囊「已更新」
11. 收尾：元素缩回 Logo 旁，出现口号「一人成军，百事可托」与金句「现在，纳米Work 可以直接给你一个网址」
12. 回到 Logo（与第一帧相同，可循环）

数据原则：图表只做示意形态，不标具体数值，不出现任何真实企业/个人信息，不编造任何产品数据。
品牌色：浅底 #f4f7fb，主文字 #1a2436，次文字 #4a5871，分隔线 #e3e9f2，卡片白色，唯一强调色 #17c37b（纳米绿）
字体：PingFang SC / Noto Sans SC（中文无衬线）
画幅：16:9（1920×1080）
</inputs>

<rules>
一个 HTML 文件。一个 canvas。
一个 draw(t) 函数。

不用 CSS transition
不用定时器
帧与帧之间不保留任何状态

一个形状，永不切镜：
每个状态都是同一个元素在改变尺寸、圆角和颜色，内容随之替换。

光标驱动整段：真实的点击、打字和一次拖拽/滑动。

真实 UI。不放占位符（但遵守上面的数据原则：示意图形不标数字）。
</rules>

<structure>
120 BPM 网格（每拍 0.5 秒），9 小节 = 36 拍 = 18 秒。
每一拍都要有事情发生。

Logo → 输入框打字 → 发送 → 专家团接单 → 浏览器看板生成 → 扫描验收 → 收窄成手机适配 → 修复打勾 → 二维码分享卡 → 复制链接 toast → 对话更新 → 新图表长出 → 口号 → Logo
</structure>

<motion>
全程使用闭式解弹簧，只允许极轻微的回弹。

一个值如果多次改变目标，就每次改变叠加一个弹簧（值始终是时间的纯函数）。

容器先开始变形，内容再进场；内容在下一次变形前先离场，文字永不重叠。

切换时加一个短促的模糊。

不要从深色直接淡入强调色，而是让一个强调色元素在状态之间移动。

Tab / 进度指示条的两条边分别挂不同的弹簧，让前沿先拉伸。

镜头缩放，让每个状态都撑满画面。

最后一帧等于第一帧，整段可无缝循环。

禁止：弹跳缓动、粒子、发光、UI 外壳上的渐变、图标线宽不统一、空镜、任何模板感。
</motion>

<export>
先按每拍渲染一帧，拼成一张缩略图检查。
修掉所有拥挤或错位的地方。

然后在无头 Chrome 里以 60fps 渲染每一帧，每帧平均 6 个子帧做运动模糊。

管道输出到 ffmpeg：
H.264 + yuv420p
</export>
